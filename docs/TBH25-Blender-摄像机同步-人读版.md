## 一、一句话说清我们在干什么

**把在 Toon Boom Harmony 里做好的摄像机，原样搬到 Blender，让 Blender 渲染的 3D 背景和 TBH 里的 2D 角色严丝合缝地对上。**

不是「让 Blender 画 3D」，也不是「让 TBH 假 3D」——是**同一个机位，两边各画各的，最后拼起来**。

---

## 二、为什么非得这么折腾

动画这行有个朴素道理：**相机是表演工具，不是渲染参数。**

动画师调机位的时候，眼睛必须盯着角色——角色在哪儿、构图舒不舒服、这一推是不是把表情推没了。如果机位在 Blender 调、角色在 TBH 画，那就是隔着两个软件做构图，来回切，效率极低。

所以分工只能是：

- **TBH 当"导演台"**：角色、表演、机位，全在这儿定；
- **Blender 当"摄影棚"**：只负责按给定机位，把 3D 环境拍出来。

这就决定了数据只能**单向**流：**TBH → Blender**。

代价也要认：Blender 变成下游，机位一改，3D 就得重渲。所以必须配一条"低清预览"的快车道，别每次都等定稿渲染。

---

## 三、整条流水线（从头到尾）

```
① Blender 建 3D 环境（成品）
        │
        │  ② 另存一份「简化版」——同一套模型，减面，坐标不动
        ▼
③ TBH 导入底模 ──► ④ TBH 里排版：等比缩放 + 挪位置
        │
        ├──► ⑤ 画角色、做绑定、加高度图/法线图/接触阴影
        ├──► ⑥ 做摄像机动画（推、拉、摇、俯仰、FOV 变化）
        │
        ▼  ⑦ 插件：逐帧导出「相机 + 底模」的数据 → JSON
        │
        ▼  ⑧ Blender 读 JSON，还原相机，渲染环境（含阴影/法线通道）
        │
        ▼  ⑨ AE / Autograph 里把 3D 背景和 2D 角色叠起来
```

每一棒的交接物：

| 环节 | 谁做 | 交出什么 | 下一棒要什么 |
|---|---|---|---|
| ①–② | 3D | 成品环境 + 简化底模（同坐标） | 底模必须是环境的"同一套几何" |
| ③–④ | 动画 | TBH 工程（含排版好的底模） | 底模只做**等比**缩放 |
| ⑤ | 动画 | 角色层 + 高度/法线/AOV/阴影 | —— |
| ⑥ | 动画 | 相机动画 | 相机挂在 Peg 上做 3D 旋转 |
| ⑦ | 技术 | `shot_camera.json` | 每帧都有相机矩阵和 FOV |
| ⑧ | 3D | 背景渲染（EXR 多通道） | 相机要和 TBH 一致 |
| ⑨ | 合成 | 最终画面 | 只负责叠，不再改机位 |

## 四、核心原理：一句话 + 一个比喻

### 一句话

**模型被均匀放大多少倍，就把相机拉近多少倍——画面完全一样。**

### 比喻

你拿手机拍一个 2 米高的雕像，站在 5 米外。
现在把雕像放大成 4 米高，但你退到 10 米外再拍——**拍出来一模一样**。

因为"东西变大"和"你退远"是同一件事的两面。反过来，模型在 TBH 里被缩小了，Blender 里就把相机推近，画面照样一样。

这就是所谓的**距离补偿**：**缩放差异，用距离去补。**

### 那为什么不能用 FOV 去补？

FOV 是**镜头**（广角 / 长焦），改它等于换镜头：广角会把近处撑大、远处压小，**透视关系变了**。

虽然单帧能凑得像，但镜头一动，视差就不对——背景的远近关系全乱。所以规矩是：

> **缩放用距离补，FOV 永远不动。**

## 五、三个真正会翻车的地方（大白话）

### 1. 相机的"转向"不在相机身上

TBH 有个操作规矩：**不要直接动模型或角色本身，要动它们身上的那根"操纵杆"（Peg）**。

相机的俯仰、横摇，也是在这根杆子上做的——**不在相机节点自己身上**。

所以如果你直接去读"相机的位置和角度"，读到的是没转过的那台相机。表现就是：**推拉全对，一抬头/一低头就错**，而且错得很隐蔽——单帧可能还看不太出来，一动就飘。

> 正确做法：**读"杆子 + 相机"加起来之后的最终位置**，不是读相机自己的数字。

### 2. FOV 不是关键帧，是"函数"

普通关键帧是"第 1 帧多少、第 24 帧多少"，中间软件自动补。

但 TBH 里 FOV 的动画是用**函数**做的，它**不在关键帧列表里**。所以：

> **只导关键帧 = 完全没导到 FOV。**

必须一帧一帧地读，才能把 FOV 的变化带出来。

### 3. 模型有个"隐形缩放系数"（0.01）

导入 3D 模型时，TBH 会让你填一个"缩放系数"（通常是 0.01），目的是让模型别大得/小得没法操作。

坑在于：**它让模型看起来变小了，但模型自己的"尺寸数字"还是 1。**

你从脚本里读尺寸，读到 1；实际渲染出来是 0.01 倍。差了 100 倍。

> 这个系数必须单独算进去。如果脚本读不到它，就手动记一笔 `0.01`，导数据时带上。

## 六、为什么要一帧一帧导，而不是只导关键帧

不是"关键帧不够用"，是两边的**过渡曲线根本对不上**。

- TBH 里两个关键帧之间怎么"缓入缓出"，是它自己的一套曲线；
- Blender 里重建出来的曲线，形状不可能一样。

结果就是：**单帧对得上，中间全飘。** 尤其是"相机停住不动、过几帧又开始动"这种，最容易露馅。

所以做法是：**每一帧都读一次、存一次**。笨，但绝不会错。

---

## 七、怎么知道自己做对了

这件事有个**白捡的验证法**，因为底模和成品环境是同一套几何：

1. 在 TBH 里定一帧，把画面存下来；
2. 用同步好的相机，在 Blender 里渲同一帧；
3. **两张图叠在一起看差值。**

差值接近零 → 对了。
差值很大 → 说明读数据时漏了什么（八成是第五节那三条之一）。

再做一段**运动测试**（推拉 + 俯仰 + FOV 变化，20 帧左右），看误差会不会**越跑越大**：

- 误差稳定 → 没问题；
- 误差越来越大 → 某个前提假设错了。

这比"看起来差不多"靠谱得多。

## 九、几个已经定下的决策，以及为什么

| 决策 | 结论 | 理由 |
|---|---|---|
| 数据方向 | **单向 TBH → Blender** | 机位是导演台定的，Blender 只是执行 |
| 合成软件 | **AE 为主，Autograph 备用** | 你的阴影/受光是"2D + 高度图/法线图"的成熟做法，AE 够用；Autograph 留作"AE 处理不了的 3D 关系"的逃生舱 |
| 角色阴影 | **和相机解耦** | 绑定阶段烘焙的接触阴影是"跟着角色走"的，相机怎么动都不会散 |
| FOV | **逐帧导** | 推拉和 FOV 两种都用，且 FOV 走函数通道 |
| 精度 | **实测 0–1 px** | 换算精确，不是"够用就行" |

## 十、名词小词典（人话版）

| 词 | 人话解释 |
|---|---|
| **Peg** | TBH 里的"操纵杆"。规矩是动杆子，不动东西本身 |
| **底模 / 代理** | 从 Blender 导进 TBH 的简化模型，给动画师当空间参照 |
| **Scale Factor** | 导入时填的"缩放系数"，让模型看起来变小，但尺寸数字不变 |
| **FOV** | 镜头有多广。越大越广角，越小越长焦 |
| **距离补偿** | 模型缩小了，就把相机推近，画面不变 |
| **轴转换 + 缩放（原称 B）** | 两个软件的"东南西北"不一样：Blender 要绕 X 转 90°，距离再乘 4.5。已实测确定，不用标定 |
| **矩阵** | 一张写着"我站哪儿、朝哪儿看、镜头多广"的身份卡 |
